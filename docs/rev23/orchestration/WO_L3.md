# WO_L3: GitHub-run witness verifier and the per-candidate PIT table

- **Milestone and gates:** 3L, gates L-P2/P3.
- **Executor:** Claude.
- **Issued:** 2026-10-29. The scope and tests below were fixed before the build started.

## Goal

Build a repeatable, read-only verifier. Given a GitHub Actions run id, it decides whether the run's factor scoring is
`PIT_PROSPECTIVE` under PLAN W.4. It also emits one table per nominated candidate and per data leg: PIT-valid,
annotated, unpreserved, or excluded, each with a reason. Apply it to run 40608600897.

## Inputs (pinned)

- The run archive: `stocks-workspace/scratch/rev23/gh_witness_archive/<run_id>/` (`run.json`, `jobs.json`,
  `logs.zip`). For 40608600897, also `scratch/rev23/gh_run_witness_40608600897/`.
- Git objects, read-only (`git cat-file`, `git show`, `git diff --name-only`), from the `screener-publish` clone.
  No fetch, checkout or reset in that clone.
- Code version: `scripts/score_factors_dual_door.py` at the run's `head_sha`. The scorer's input paths are taken from
  this file. The workflow's `git add` list is taken from `.github/workflows/<workflow>.yml` at `head_sha`.

## Scope

- **Create only** `stocks-workspace/scratch/rev23/m3l_verifier/`: `m3l_gh_run_witness.py`,
  `test_m3l_gh_run_witness.py`, `out/`.
- **Touch nothing else.**
- **Allowed operations:** read; local git object reads; pytest with system Python 3.12. No network, no GPU.
- **Operator-excluded names** (SENEA, SENEB, MOV, MG) stay in the table, flagged `operator_excluded`, with no further
  investigation.

## Checks

**Run level.** Any failure here makes the whole run FAIL.

| Check | Requirement |
|---|---|
| R1 | `run.json` conclusion is `success`. |
| R2 | `head_sha` is taken from `run.json`. The runner type comes from `jobs.json`: GitHub-hosted, or self-hosted with an annotation. |
| R3 | The log contains a push line `<old>..<new>  main -> main` whose `<old>` is a prefix of `head_sha`. The output commit `<new>` exists locally and its first parent is `head_sha`. |
| R4 | Decision time = `run.json.updated_at` (GitHub server time). The push line's timestamp must be at or before it. |
| R5 | The log shows `STEP DONE: score_factors_dual_door rc=0`. |

**Input classification.** Every scorer input path gets exactly one class:

| Class | Meaning |
|---|---|
| `HEAD_TREE` | Identical blob in `head_sha` and the output commit. It existed on GitHub when the run was created. |
| `IN_RUN_COMMITTED` | Changed in the output commit. Produced inside the witnessed run window, and its bytes are preserved. |
| `IN_RUN_UNPRESERVED` | Regenerated by a chain step that ran before the scorer, but not in the workflow's `git add` list. Causally PIT; bytes not preserved. |
| `PREVIOUS_OUTPUT` | The scorer's own previous output, read for hysteresis. Its `head_sha` blob is the input. |
| `MISSING` | Not present. |

**Per candidate.** One row for each of the output's `nominated_tickers`, across these legs:

| Leg | Source | Statuses and flags |
|---|---|---|
| SEC fundamentals | `fundamentals_history`, plus the `shares_cover` filed date | `PIT_PROSPECTIVE` if present. Excluded `post_decision_filed` if the filed date is after the decision date. `MISSING` if absent. |
| Battery | `fundamentals_battery` | |
| Price | `price_history` | Annotation `undated_series`: the price lists carry no dates. |
| Momentum | `momentum_state` | Class as above; `price_asof` must be at or before the decision date. |
| EPS | `eps_trajectory` | Annotation `eps_null_record` when every numeric value is null. |
| MRI | committed snapshot | Ranking date and age; the branch comes from the log. |
| Factor rank | output profile | |

The candidate status is the worst status across its legs. Counts must reconcile to `nominated_count`.

## Acceptance tests

- **Positive:** run 40608600897 passes R1–R5. The table has 160 rows, and the counts by status sum to 160.
- **Negative controls** (pytest, synthetic metadata):
  - an output commit whose parent ≠ `head_sha` makes R3 fail;
  - a missing push line makes R3 fail;
  - a `shares_cover` filed date after the decision date is excluded as `post_decision_filed`;
  - a scorer input path absent from both trees is `MISSING`;
  - a conclusion of `failure` makes R1 fail.
- **One independent recomputation:** `nominated_count` and one candidate's leg statuses are recomputed by hand from the
  git blobs.

## Budget and stop conditions

- At most 2 approaches.
- Stop if git objects for the run are not in the local clone. Report it; do not fetch.
