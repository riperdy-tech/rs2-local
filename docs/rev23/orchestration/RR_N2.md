## Replay and older builder versions (the question in the brief)

**Replay can only rebuild with the current builder.** A verified packet stored by builder v3 does not replay: it has no `regime`, its `builder_version` and `builder_code` differ, and v4 can select a different set of 8-Ks (Item 1.02). Replay reports it as not identical, with the first difference `$.builder_version` (`test_a_packet_of_the_previous_builder_version_is_rebuilt_by_the_current_one_and_not_identical`). I did not add compatibility. Consequence: the 3M packets in `cache/m3m/packets` (and the M-LIVE replay evidence) stay the records of v3 and fail `python -m qwen_c.replay` under this branch, as `SPEC_m3n` section 3 already says ("the 3M packets are not rebuilt").

3. **`stocks_json_absent`** is "stocks.json does not exist at the commit" (`git cat-file -e`). That is "no commit at or before touched it", and it also refuses a commit at which the file was deleted.
4. **Archival refusals I added:**
   - `argument_not_for_regime`: a `verified_record` with archival, or a `cik` with verified;
   - `regime_invalid`;
   - `cik_invalid`: not 1-10 digits, zero, a bool, or a float.

   The point is to make a mistaken call visible instead of ignoring an argument.
5. **`frame_commit_after_T`** is checked before the blobs are read; a commit time equal to T is accepted. In the verified regime the order is unchanged.
6. **CIK source.** Map and argument agreeing gives `cik_source: "cik_map"`. `cik_source` is a top-level packet field, present in archival packets only. 8. **Replay.** A packet with no `regime` is treated as `verified`. A `cik_source` of `argument` passes the header's `cik` again as the argument; anything else reads the map.
9. **Runner subset rules.**

## Things I found that matter for N3 to N6

- **`T_before_filings_recent`** still applies to archival packets. `filings.recent` has about the last 1000 filings, so a name that files a lot (Forms 4, 424B) may not reach back to a T in 2025-12 or early 2026, and the builder will refuse it. The brief keeps evidence selection unchanged; N5 should expect some refusals and count them as `not_in_packet`/excluded, not as model misses.
- **Going concern (C2) may not be in the packet.** Evidence is statements F1-F3, MD&A, Part II Item 1A and 8-K text. A going-concern paragraph that sits in the financial-statement notes or the audit report is outside that. Item 1A and MD&A usually repeat it, but not always. Baseline B and Qwen are measured on the same packet, so the comparison is fair; the `not_in_packet` count for C2 will probably be higher than for the 8-K classes.
- **Other 8-K slots:** at most four, 120 days back. An event whose 8-K is older, or crowded out by newer 8-Ks, is `not_in_packet` at T2 (T1 + 20 sessions) by construction.
- **The default screener repository for the archival regime is still the publish clone**, whose history starts 2026-08-26. A frame commit from 2025-12-14 is not in it: `git rev-parse` fails with a plain `PacketError`, not a refusal. N5 must pass `--screener-repo` (the stock-screener development checkout).
- **Line endings.** The working tree is CRLF under `core.autocrlf=true` while git stores LF. `builder_code` normalises CRLF to LF, so packets built on either checkout agree.
- Nothing in the brief conflicted with the code, so no part was stopped.
