## Addendum, 2026-10-29 (overnight): verifier v1.2, and a sweep of every dual-door run

**Changes after the first version.** Each was found by running the verifier on more runs, and each is covered by a
test: 13/13 pass.

1. **Two-job workflow (data fetch).** In v1.0 the scoring base had to be `head_sha`. The score job of the data-fetch
   workflow checks out the fetch job's push instead.
2. **Run's own output commit.** The output is now the `[main <sha>]` commit printed by the scoring job, and the base
   is that commit's parent. When the push had to merge another writer's commit (run 37325951878), v1.0 would have
   taken the merge, which carries someone else's changes, as the output.
3. **How the base is witnessed.** The base is witnessed by the scoring job's own checkout line in GitHub's log:
   `HEAD is now at …` on the PC runner, or `git log -1 --format=%H` followed by the SHA on GitHub-hosted runners. It
   can also be `head_sha` itself.
4. **Writers.** A writer counts only if this run's scoring job ran it, judged by its name in the job log. `mri_sync`
   counts only if its log line says "copied from". A directory `git add` (`public/data/mri/`) now counts as committing
   the files in it.
5. **Robustness.**
   - Missing input files are reported, not crashes.
   - Short commit ids are resolved as commits, because some 7-character ids are ambiguous in `stock-screener`.
6. **Verdict rule.** An input changed by an unknown writer (`UNEXPLAINED_CHANGE`) fails the run. A writer missing
   from an older code version is only reported.
